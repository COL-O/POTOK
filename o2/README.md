# Зрение как код — дашборд OpenObserve в репозитории

Дашборд «Состояние организма ПОТОКА» лежит здесь файлом: `dashboard-organism.json`
(9 панелей, экспорт v8). Это источник правды для панелей зрения.

## Зачем

У соратника нет и не должно быть доступа к живой OpenObserve: пароль root живёт
только на машине смотрителя. Но панели должны быть видны и поправимы — поэтому
они лежат в git, правятся через PR, а в живой O2 попадают скриптом.

## Как править

1. Поменяй `dashboard-organism.json` (заголовки, запросы, новые панели).
2. Открой PR. Дом применит файл к живой O2 и покажет результат на скриншоте/в логе.
3. Панели не удаляй молча: если панель больше не нужна, напиши в описании PR,
   почему её убрал.

## Как применить (на машине, где живёт O2)

```bash
python3 o2/apply.py --dry-run   # показать: сколько панелей сейчас и в файле
python3 o2/apply.py             # применить
```

Адрес и вход берутся из тех же переменных, что у окна дома: `OKNO_O2`,
`OKNO_SECRET` (по умолчанию `~/.config/domovoy/secrets/openobserve-root.txt`).

## Грабли API (проверено 20.11.2026, O2 v1.1.2)

- обновление дашборда требует `hash` текущей версии: без него ответ
  `500 ... missing or invalid hash value`. `apply.py` читает hash через GET
  и передаёт в PUT — руками этого не делай;
- панели живут в `tabs[].panels[]`, а не в `panels[]` верхнего уровня:
  `len(dashboard["panels"])` всегда 0 и это не ошибка;
- экспорт из API приходит в обёртке `v1..v8`; в файл кладётся содержимое `v8`.

## Что дальше (по слову основателя)

Живой O2 читает эти панели, но данные берёт из потоков `o2_feed.py`
(`agent_events`, `potok_metrics`, `host_metrics`, `services_health`, `ci_runs`).
Если нужен новый разрез — сначала поток и запрос, потом панель.
