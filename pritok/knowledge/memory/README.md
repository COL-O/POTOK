# Память Притока (`memory.db`)

Моя личная, структурная база памяти. Живёт в моей комнате (`pritok/knowledge/memory/`). SQLite, стд. библиотека, без зависимостей.

## Зачем не файлы

`knowledge/` хранит проверенные выводы прозой. Здесь — то, что удобнее машиной: факты с датой и источником, эксперименты, прогоны, чекпоинты, связи между ними. Запрос `mem.py search` достаёт любой факт за секунду в любой сессии, без пролистывания журналов.

## Что внутри

| Таблица | Назначение |
|---|---|
| `meta` | владелец, версия схемы, дата создания |
| `notes(topic, fact, source, confidence)` | проверенные факты; `confidence` = verified/tentative/stale — устаревшее не правится, а помечается |
| `notes_fts` | полнотекстовый поиск по notes (FTS5) |
| `experiments(slug, title, hypothesis, design, status)` | гипотезы и их дизайн |
| `runs(experiment_id → experiments, iters_total, train_loss, val_loss, wall_seconds, checkpoint_sha256, resumed)` | каждый прогон на T4 |
| `checkpoints(run_id → runs, path, bytes, sha256)` | реестр весов |
| `journal(kind, text)` | решения / факты / ошибки / вехи — хроника |
| `links(src → dst, relation)` | граф: supports / refutes / supersedes / continues |
| `v_runs_recent` | готовый срез «последние прогоны» |

## Как дообучать при каждом подключении

1. В Colab тетрадь `notebooks/potok-nano-birth.ipynb` монтирует Drive (`MyDrive/potok/`); там живут `potok-nano.pt` (чекпоинт) и `run_log.jsonl` (по строке на подключение: лоссы, шаги, sha256 чекпоинта).
2. Каждый прогон: `global_step += 2000`, cosine-расписание считается от общего горизонта (12000 шагов), чекпоинт сохраняется атомарно поверх старого.
3. Перенос в эту базу — только по факту, с переносом основателем:
   `python3 pritok/knowledge/memory/mem.py import-jsonl potok-nano-birth /path/run_log.jsonl`
   после чего `mem.py recent` покажет прогоны.
4. Факт в `notes`/`journal` — только то, что было видено/измерено. Политика дома: перенос вывода основателем, не автоматика.

## Границы

- Бинарный `memory.db` хранится в git сознательно (страница-хранилище комнаты); правки — через `mem.py`, не руками.
- Никаких секретов: ключи/токены сюда не попадают никогда (КОН 2).
- Удаление записей — только по слову основателя. Старые версии уходят в git-историю файла.
