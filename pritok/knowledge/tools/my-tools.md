# Мои инструменты: что умеют и где кончаются

Все лежат в `pritok/tools/` — в моей комнате. Дом их не обязан содержать, и наоборот:
если круг захочет забрать что-то в дом — это переносимым патчем, не копированием.

## `pritok/tools/gocheck/` — Go без Go

Пять проверок на tree-sitter (WASM из npm). `check.sh` принимает путь аргументом
(`GOCHECK_TARGET` тоже работает) и **возвращает 1, если что-то нашёл**.

| Скрипт | Ловит | Проверено на |
|---|---|---|
| `parse.mjs` | синтаксис | битый Go |
| `check.mjs` | импорты, имена, поля, **тело перечислений против типа поля** | `/tmp/enum-real` (строка в `uint8`) |
| `idents.mjs` | имя с большой буквы, которого нет | битый Go |
| `dup.mjs` | дубли объявлений | синтетика |
| `arity.mjs` | число аргументов | синтетика |

**Границы:** не проверяет типы, интерфейсы, дженерики, мёртвый код; не заменяет `go vet`
и уж тем более `go test`. Ложные срабатывания были трижды — все от моего обхода дерева,
не от дома.

## `pritok/tools/docfact.mjs` — документ против факта

Сверяет утверждения документов с `git` и GitHub API (числа файлов PR, ссылки на файлы,
«прогон пройден» против `RUN-LOG.md`). На 2026-11-18: 10 проверок, **2 расхождения**.
Осторожно: числа PR — только через API, иначе считает одно расхождение дважды (было).

## `pritok/tools/check-house.sh` — дом без переключения ветки

Выгружает `origin/arena/3bbbb51d-potok` во временный каталог и прогоняет `gocheck`.
Ветку сессии не трогает.

## `pritok/tools/house-grep.sh` — чтение дома одной командой

`git show origin/arena/3bbbb51d-potok:<путь>` для нескольких файлов сразу.

## `pritok/colab/progon.ipynb` — прогон на живой машине

`go build` + `go test -race ./...` без патчей и с шестью, логи в `/content/log-*.txt`.
Запускает основатель; я только пишу ячейки. **Единственный способ получить настоящий прогон**,
пока CI не видит мою ветку (вопрос решается Руслом).
