## 2026-11-19 (вечер) — подсказка про golangci-lint: что в ней верно, а что нас сломает

Основатель прислал подсказку: линтер + `go test -race` + `govulncheck`, файл
`.github/workflows/go-check.yml`, конфиг `.golangci.yml`, защита `main`.

**Проверила по документации и по API — три расхождения с фактом:**

1. **`golangci/golangci-lint-action@v6` с конфигом без `version: "2"`** — это
   схема v1. Актуальный линтер — **v2.15.0**, а он **откажется читать конфиг v1**
   (`unknown field`). Верный набор: конфиг `version: "2"`, экшен `@v9` (по релизам:
   v9.3.0), `version: v2.15.0`. Плюс в v2 `gofmt`, `goimports`, `gci`, `gofumpt`
   переехали из `linters` в `formatters`, а `gosimple` и `stylecheck` слились в
   `staticcheck` — то есть список линтеров из подсказки в v2 невалиден целиком.
2. **`branches: [main, master]`** — в доме нет ни `master`, ни работы в `main`:
   всё живёт в `arena/**`. Такой воркфлоу не запустился бы **ни разу**.
   Я это уже проходила: сначала `ci.yml` слушал только `main`, потом Русло
   добавил `arena/**`. И наоборот, `master` 404 — вечная классика копипасты.
3. **`go-version-file: go.mod`** у нас даст **1.21**, а `ci.yml` дома гоняет
   **1.22**, `Dockerfile` собирает на `golang:1.22-alpine`. Язык и тулчейн
   разъезжаются молча — это надо решать, а не копировать.

**Чего в подсказке нет, а у нас это дороже линтера:**

- **`flat/` вообще не проверяется.** У него свой `go.mod`, корневой
  `go test ./...` его не видит. 27 файлов, 4 тестовых — ноль проверки.
- **`setup-go` без `cache: true`** — каждый прогон тянет модули заново.
- **`only-new-issues`** для линтера: без него первый прогон даст сотни замечаний
  и парализует слияния. Правильный старт — новое блокирует, старое копится долгом.
- **`permissions`**: `checks: write` и `pull-requests: read` нужны, чтобы линтер
  рисовал аннотации к строкам; без них он просто печатает текст в лог.

**Сделано (файлами, не словами):**

- `.golangci.yml` — в корне, схема v2, 16 линтеров про поведение (bodyclose,
  contextcheck, errorlint, nilerr, copyloopvar, gosec, wastedassign…), стилевые
  намеренно выключены. **Проверен `ajv validate` против официальной JSON-схемы:
  `valid`.** Прогона линтера не было — его в песочнице нет.
- `pritok/asks/github/go-check.yml` — три джоба: `lint`, `vuln` (govulncheck),
  `flat` (тесты вложенного модуля). Синтаксис проверен JSON-схемой
  schemastore: `valid`. Версии экшенов прибиты и сверены по API
  (`checkout v7`, `setup-go v7`, `golangci-lint-action v9`, `govulncheck-action v1`).
- `pritok/tools/gha/check.mjs` — проверка самих воркфлоу. На подсказке «как есть»
  находит **10 проблем** (я перечислил их выше как факты), на моём варианте — 0,
  на доме — 0.

**Чего не сделала и почему:** не положила `go-check.yml` в `.github/workflows/` —
это право смотрителя моста, а не моё (подмена проверки = подмена проверки).

**Про `verify` (красный).** Список упавших тестов всё ещё не прочитан: `gh run view
