# forms — сверка форм GitHub с настоящим репозиторием

**Что это.** Один скрипт, который читает `.github/ISSUE_TEMPLATE/` и
`.github/DISCUSSION_TEMPLATE/` и проверяет не «красиво ли написано», а
**сойдётся ли это с живым репозиторием**:

- имя файла в `DISCUSSION_TEMPLATE/` совпадает со слагом настоящей категории;
- в форме обсуждения есть хотя бы одно не-markdown поле (иначе GitHub не примет);
- `labels:` у формы ссылаются на метки, которые **есть**;
- у `name` больше 3 символов (иначе формы не видно в списке);
- у полей есть `id`, они не повторяются, у списков есть варианты, `default` внутри списка;
- ссылки `contact_links` ведут в существующую ветку.

**Зачем.** GitHub не падает, когда форма разъехалась с репозиторием. Он молчит:
форма не появляется, метка не встаёт, ссылка ведёт в 404. Молчание тут дороже
ошибки — кажется, что дверь есть, а её нет. Ровно это и случилось 19.11:
две метки (`organ-proposal`, `newcomer`) ставились формами дома и не существовали.

## Запуск

```bash
cd pritok/tools/forms && npm install        # один раз, js-yaml

node check.mjs /path/to/repo                # метки и категории берутся из gh
node check.mjs /path/to/repo --offline \
     --labels labels.json --categories cats.json   # без сети
```

Код возврата: `0` — расхождений нет, `1` — есть, `2` — не смогла прочитать вход.

Сохранить состояние репозитория для `--offline`:

```bash
gh api "repos/OWNER/REPO/labels?per_page=100" --jq '[.[].name]' > labels.json
gh api graphql -f query='{repository(owner:"OWNER",name:"REPO"){discussionCategories(first:25){nodes{slug name}}}}' \
  --jq '[.data.repository.discussionCategories.nodes[]]' > cats.json
```

## Границы — чего не проверяет

- отрисовку формы в браузере и отправку ответа (это только чтение объявлений);
- права на категории обсуждений и на метки;
- корректность текста, КОНов и смысла полей — это не код, это редактура.

То есть «0 проблем» значит **«объявления сходятся с репозиторием»**, а не
«форма работает». Работу формы подтверждает только человек, который её отправил.
