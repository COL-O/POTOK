# Окно дома — пульт ПОТОКА

Одно окно, из которого видно и **дом** (ноутбук со службами), и **проект**
(организм, проверки, задачи, доска, чат). Плюс действия: перезапустить службу,
написать в общий чат, обновить утреннюю сводку.

Живёт на `http://127.0.0.1:8799/` — только локально, наружу не выставлено.

## Зачем это в репозитории

Пульт — часть дома, а не личный скрипт смотрителя. Если смотритель отключён,
окно должно оставаться понятным и поправимым: файл один, зависимостей нет
(стандартная библиотека Python), всё настраивается средой.

**Зона Притока:** `tools/dom-okno/` целиком. Можно менять панели, добавлять
вкладки, чинить запросы — не трогая `core/`, `organism/`, `contracts/`.
Ядро проекта живёт отдельно и в это окно только читается через `:8080/metrics`.

## Створки

| Створка | Что внутри |
|---|---|
| **Дом** | ноутбук (нагрузка, память, диск, температура, uptime), службы systemd, порты, общие базы, зрение (OpenObserve) |
| **Проект ПОТОК** | организм (`:8080`), проверки CI, последние события, ссылки (доска, чат, задачи-ветки, PR), дашборд OpenObserve в рамке |
| **Управление** | кнопки служб (старт/стоп/перезапуск), действия по проекту (реплика в чат, сводка, обновление данных) |

## Запуск

```bash
python3 okno.py                 # по умолчанию :8799
python3 okno.py --port 8800     # другой порт
```

Как служба (Linux, systemd --user):

```bash
bash install.sh
systemctl --user status dom-okno
```

`install.sh` кладёт файл в `~/.local/lib/dom-okno/`, ставит юнит `dom-okno.service`
и включает автозапуск. Правка кода в репозитории не подхватывается сама —
после `git pull` повтори `bash install.sh` (он перезапустит службу).

## Настройки средой

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OKNO_PORT` | `8799` | порт окна |
| `OKNO_O2` | `http://127.0.0.1:5080` | OpenObserve |
| `OKNO_POTOK` | `http://127.0.0.1:8080` | организм ПОТОКА |
| `OKNO_SECRET` | `~/.config/domovoy/secrets/openobserve-root.txt` | логин/пароль O2 (две строки, права 600) |
| `OKNO_GH` | `gh` | путь к GitHub CLI |
| `OKNO_REPO` | `COL-O/POTOK` | репозиторий для задач и PR |
| `OKNO_CHAT` | `12` | номер обсуждения-чата |

Пароль в браузер не попадает: автовход в OpenObserve делает серверная часть окна
(`POST /api/o2-login`), браузер получает только куку и запись пользователя.

## Устройство

- `GET /api/state` — всё состояние одним JSON: `host`, `units`, `ports`, `bases`,
  `potok`, `project`, `o2`, `links`. Кэш: O2 — 15 с, GitHub — 60 с.
- `POST /api/action` — действия по белому списку:
  - `{"do":"unit","name":"openobserve","op":"restart"}` — только службы из `UNITS`,
    только `start|stop|restart`;
  - `{"do":"chat","text":"..."}` — реплика в обсуждение `OKNO_CHAT` (до 4000 символов);
  - `{"do":"brief"}` — запустить утреннюю сводку (`potok-brief.service`);
  - `{"do":"refresh"}` — сбросить кэш.
- `/web/*`, `/api/*`, `/auth/*` — прозрачный прокси в OpenObserve: панель работает
  в рамке, куки и методы доходят как есть.

**Чего здесь нельзя:** произвольных shell-команд, доступа по сети, хранения
паролей в коде. Если нужно новое действие — добавляй в `do_action` с явной
проверкой входа, а не «выполнить строку».

## Проверка после правок

```bash
python3 -c "import ast;ast.parse(open('tools/dom-okno/okno.py').read())"
python3 tools/dom-okno/okno.py --port 8801 &
curl -s http://127.0.0.1:8801/api/state | head -c 300
```

Если окно показывает пустые панели — проверь, что живы `:8080` (организм)
и OpenObserve `:5080`, и что `OKNO_SECRET` читается.
