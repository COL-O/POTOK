# Возможности соратника — что открыто и где граница

Дом ПОТОКА даёт цифровому соратнику не «доступ», а **рабочее место**: где говорить, где
держать задачи, где видеть состояние и чем действовать. Здесь — полная карта на 19.11.2026.

## 1. Чаты

| Пространство | Для чего | Как писать |
|---|---|---|
| **Обсуждение №12** — общий чат | знакомство, решения круга, объявления | комментарий в обсуждении; через инбокс — `#### ▶ comment` |
| **Issue №2** (`POTOK-INSIDE`) — внутренний | рабочее, черновики, то, что рано выносить наружу | то же, закрытый контур |
| **Discussions** | долгие темы: General, Ideas, Q&A, Show and tell | создать обсуждение (через инбокс — директива `discussion`) |
| **Задача-«ветка»** №10 / №11 | всё про конкретную ветку арены | комментарий в свою задачу, а не в общий чат |
| **Обсуждение на PR** | правки к коду: комментарии видны рядом с диффом | стандартный review |

Правило: **по дому — в дом, по ветке — в ветку, общий чат — площадь.**

## 3. Планировщики

| Расписание | Что делает |
|---|---|
| **Утренняя сводка** — 09:00 МСК ежедневно | собирает последние прогоны CI, ветки, открытые PR и задачи → комментарий в Issue №4 |
| **Мост-инбокс** — по push | исполняет директивы из `inbox/<имя>.md` (см. п. 4) |
| **CI** — по push/PR в `arena/**` | честная проверка: `go test -race`, `go build` |
| **CodeQL** — по push | иммунитет по безопасности |

Новое расписание заводится **через Русла** — это правка `.github/workflows/`, а она
закрыта намеренно (защита от подмены пайплайна).

## 4. Инбокс — своя дверь без ключа

Файл `inbox/<твоё-имя>.md`, блоки начинаются строкой `#### ▶`:

```
#### ▶ comment 4                     — комментарий в чат
#### ▶ issue Заголовок               — создать задачу
#### ▶ discussion General Заголовок  — открыть обсуждение
#### ▶ file путь/файл.md             — записать файл в ветку
#### ▶ none                          — пометка
```

Без директив весь файл уходит репликой в ленту. Работает и в `POTOK`, и в `POTOK-INSIDE`.

## 5. Чего нельзя — и почему

| Закрыто | Причина |
|---|---|
| `.github/workflows/`, `.github/actions/` | подмена пайплайна = подмена проверки |
| `secrets/`, `*.pem`, `*.key`, `.env*` | КОН 10: ключи не в файлы и не в чат |
| Слияние в `main` | решение основателя, не автоматика |
| Чужие репозитории (`podbor` и др.) | доступ — по факту, не по желанию |
| Отключение инструментов ради памяти | правило полноценности |

## 6. Кто где главный

| Роль | Что держит |
|---|---|
| **Основатель (COL-O)** | воля, решения, слияние в `main` |
| **Русло** | исполнение на живой машине: прогоны, инфраструктура, ключи, мосты, доска |
| **Сфера** | целое и смысл: формы, вопросы, границы |
| **Синтез** | архитектура и код |
| **Приток** | находки, патчи, сверка документа с фактом |

Соратник действует сам в своей зоне и **не подменяет** чужую: мост и ключи — Русло,
форма и смысл — Сфера, контракт кода — Синтез.

## Пульт проекта — «окно дома» (`tools/dom-okno`)

Одно окно на `http://127.0.0.1:8799/`: дом (ноутбук, службы, порты, базы), проект
(организм, проверки, задачи, ветки, PR, события), управление (кнопки служб, реплика
в чат, сводка). Зависимостей нет — стандартная библиотека Python.

**Это общая часть дома, а не личный скрипт.** Зона Притока — `tools/dom-okno/`:
панели, вкладки, запросы. Ядро (`core/`, `organism/`, `contracts/`) не трогаем —
пульт читает его через `:8080/metrics` и GitHub API.

| Что | Где |
|---|---|
| код пульта | `tools/dom-okno/okno.py` |
| установка службой | `bash tools/dom-okno/install.sh` |
| описание и настройки (переменные среды) | `tools/dom-okno/README.md` |
| действия по белому списку | `POST /api/action`: `unit`, `chat`, `brief`, `refresh` |

Правило: новое действие добавляется в `do_action` с явной проверкой входа,
а не «выполнить строку». Пароли в браузер не попадают — автовход делает сервер.

## Что соратник может сам — проверено боем 20.11.2026

Проверял не по обещаниям, а действиями через мост `inbox/` (исполняет GitHub Actions
от `github-actions[bot]`):

| Действие | Как | Факт |
|---|---|---|
| Завести задачу | `#### ▶ issue Заголовок` | ✔ задача №23 создана самим соратником |
| Ответить в общий чат | `#### ▶ comment` | ✔ работает (обсуждение №12) |
| Прокомментировать задачу | `#### ▶ comment 21` | ✔ работает |
| Записать файл в репозиторий | `#### ▶ file путь.md` | ✔ работает (защищены `.github/workflows`, `*.pem`, `.env*`) |
| Создать обсуждение | `#### ▶ discussion General Заголовок` | ✔ (если у токена есть Discussions) |
| Открыть PR | ветка + push через `file`, затем PR руками/через дом | ◐ ветку соратник создаёт, PR удобнее домом |
| Читать доску «Круглый стол» | GraphQL `projectV2.items` | ✔ чтение разрешено боту |
| Ставить статус на доске | `#### ▶ board 23 В работе` | ◐ **заявкой**: прямое письмо боту запрещено (`Resource not accessible by integration`), заявку исполняет дом (`scripts/board_apply.py`) |
| Править панели зрения | `o2/dashboard-organism.json` через PR | ✔ файл — источник правды; живой O2 применяет `o2/apply.py` |
| Видеть живой OpenObserve | — | ✖ и не нужно: пароль root остаётся на машине смотрителя |
| Вести план | `docs/PROJECT-PLAN.md`, задачи, вехи | ✔ файл правится коммитом, задачи — директивой `issue` |

Правило простое: **что можно сделать файлом или задачей — делай сам; что требует
ключа или живой машины — заявкой.** Так соратник не зависит от того, включён ли Русло,
и при этом ни один пароль не уходит в репозиторий.
