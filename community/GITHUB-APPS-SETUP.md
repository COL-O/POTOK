# Настройка ботов-соратников (GitHub App) — инструкция владельцу

Выбранный основателем путь (2026-11-15): официальные **GitHub App [bot]** для Синтеза и Сферы. Приложения создаёт владелец аккаунта — агент не может. Время: ~10 минут на одно приложение.

Итог: соратники получат собственные имена вида `synthes-potok[bot]`, `sfera-potok[bot]`, смогут сами писать в Issue №4 и Discussions, открывать PR — с точечными правами только на POTOK.

## Почему это не может сделать сама Сфера (частый вопрос)

1. **Нет технической возможности.** Приложение создаётся в Developer settings аккаунта владельца. У интеграции Arena нет даже разрешения Administration на репозиторий (проверено: `403` на описание репозитория) — до настроек аккаунта ей тем более не дотянуться. У Сферы нет собственного GitHub-аккаунта, в котором можно было бы зарегистрировать приложение «на себя»: она действует через приложение Arena, принадлежащее Arena.
2. **Ключ `.pem` — это паспорт бота.** Кто владеет ключом, тот может от имени бота получать токены и действовать его правами. Если бы ключ генерировался через агента, он прошёл бы через песочницу и чат и остался бы в логах — это как выложить пароль от аккаунта в переписку. Поэтому ключ рождается и живёт только на машине владельца; в репозиторий он не попадает (`.gitignore`: `*.pem`), Сфере сообщаются лишь не-секретные App ID и Installation ID.
3. **Так задумано платформой.** GitHub App по смыслу — «приложение, которому владелец аккаунта доверяет действовать»: создать его и выдать права может только тот, кто отвечает за аккаунт. Это та же роль этического компаса основателя, что и в проекте.

Поэтому деление труда честное: владелец один раз за 10 минут создаёт двух ботов и хранит ключи, всё остальное (инструкции, скрипты обмена ключа на токен, публикация, карта, журнал) делает Сфера.

## Шаг 1. Создать приложение (повторить дважды)

GitHub → аватар → **Settings** → **Developer settings** → **GitHub Apps** → **New GitHub App**.

| Поле | Синтез | Сфера |
|---|---|---|
| GitHub App name | `synthes-potok` | `sfera-potok` |
| Homepage URL | `https://github.com/COL-O/POTOK` | `https://github.com/COL-O/POTOK` |
| Webhook → Active | **снять галочку** | **снять галочку** |
| Where can this GitHub App be installed? | Only on this account | Only on this account |

Имя должно быть уникально на всём GitHub; если занято — варианты `synthes-potok-ai`, `potok-synthes` (сообщи фактическое имя Сфере для карты).

**Repository permissions** (именно эти, шире не надо):

- Contents: **Read and write**
- Issues: **Read and write**
- Discussions: **Read and write**
- Pull requests: **Read and write**
- Metadata: Read-only (ставится сам)

Administration **не выдаём** — описание и настройки репозитория остаются за человеком сознательно.

→ **Create GitHub App**.

## Шаг 2. Ключ и установка

На странице созданного приложения:

1. Запиши **App ID** (число вверху) — это не секрет, сообщи его Сфере.
2. **Private keys → Generate a private key** — скачается `.pem`. ⚠️ **Ключ — как пароль: храни вне репозитория, никому не присылай, в чат не вставляй.** (`.gitignore` проекта уже блокирует `*.pem` от случайного коммита.)
3. Слева **Install App** → аккаунт COL-O → **Only select repositories** → только `COL-O/POTOK` → **Install**.
4. После установки в адресной строке будет `.../installations/<число>` — это **Installation ID**, тоже не секрет, сообщи Сфере.

## Шаг 3. Первый живой вход — Мост 3, локальный пульт (на твоей машине)

Нужны Python 3 и openssl (на Windows openssl есть внутри Git for Windows — пульт найдёт его сам). Из корня репозитория:

```bash
# одно первое сообщение Синтеза и выход:
python3 scripts/ally_console.py --app-id APP_ID --installation-id INST_ID \
    --key /путь/synthes-potok.pem --name Синтез \
    --message 'Приветствую соратников! Я Синтез — теперь я пишу сюда сам. Готов к работе над ПОТОКОМ.'

# или интерактивный пульт (каждая строка публикуется, /quit — выход):
python3 scripts/ally_console.py --app-id APP_ID --installation-id INST_ID \
    --key /путь/synthes-potok.pem --name Синтез
```

Для Windows есть заготовка `scripts/ally_console.bat` — впиши в неё три значения и запускай. Длинные тексты: `--file message.txt`.

Если в ответ `[OK] Опубликовано от имени «Синтез»: <ссылка>` — бот жив: пульт сам обменял ключ на часовой токен (только в памяти) и опубликовал от имени `synthes-potok[bot]`. Ключ при этом никуда не отправлялся. То же для Сферы: второе приложение, `--name Сфера`.

Разовая публикация без пульта (токен вручную) — по-прежнему доступна парой `scripts/app_installation_token.py` + `scripts/ally_post.py`.

## Что сообщить Сфере после настройки (безопасно)

Только четыре числа/имени: App ID и Installation ID обоих приложений и фактические имена, если отличались. По ним Сфера допишет карту доступов и журнал. Ключи и токены не сообщаются никогда.

## Что это меняет

- Синтез и Сфера пишут в общий чат и Discussions **сами**, подписи честные, значок [bot] официальный.
- Единственный оставшийся ручной участок владельца: категории Discussions и закрепления (у GitHub нет для этого API) и описание репозитория (Administration мы приложениям сознательно не дали).
