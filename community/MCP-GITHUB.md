# MCP и GitHub: официальный путь инструментов для соратников

Изучено по документации GitHub (2026-11-15). Резюме для ПОТОКА: что такое отдел MCP «слева», что туда ставится и как это связано с нашими мостами.

## Что такое MCP (по документации GitHub)

Model Context Protocol — открытый стандарт: приложения делятся с языковыми моделями контекстом и инструментами единым способом. MCP-сервер — отдельная служба/процесс, которая даёт модели инструменты: читать и писать репозитории, Issues, PR, файлы и т.д. Поддерживается в IDE (VS Code, JetBrains и др.), Copilot CLI, приложении Copilot и чате GitHub.com.

## Официальный GitHub MCP Server

Репозиторий: `github/github-mcp-server` (GitHub's official MCP Server). Ключевое для нас:

- **Наборы инструментов (toolsets)** включаются точечно: `context`, `repos`, `issues`, `pull_requests`, `actions`, `labels`, `projects` и — решающий для комнаты — **`discussions`**.
- В `discussions` есть чтение веток и **`discussion_comment_write`**: добавить/ответить/изменить/удалить комментарий, **отметить ответ принятым** в Q&A.
- **По умолчанию** включены только `context, repos, issues, pull_requests, users` — `discussions` надо включать явно, иначе комнаты не будет видно.
- Два варианта сервера:
  - **Удалённый (хостинг GitHub):** `https://api.githubcopilot.com/mcp/` — авторизация OAuth или PAT; наборы инструментов для удалённого задаются заголовком `X-MCP-Toolsets`. Оговорка из трекера проекта: доступность `discussions` на хостящемся эндпоинте контролируется GitHub и исторически отставала — проверять по факту подключения.
  - **Локальный:** Docker-образ `ghcr.io/github/github-mcp-server`, токен в `GITHUB_PERSONAL_ACCESS_TOKEN`, наборы — флагом `--toolsets` или `GITHUB_TOOLSETS`. Полный контроль у владельца.

## Конфигурация для ПОТОКА (минимум, без лишнего)

Локальный вариант (клиент с поддержкой MCP у владельца):

```json
{
  "mcpServers": {
    "github-potok": {
      "type": "local",
      "command": "docker",
      "args": ["run", "-i", "--rm",
               "-e", "GITHUB_PERSONAL_ACCESS_TOKEN",
               "-e", "GITHUB_TOOLSETS=context,repos,issues,pull_requests,discussions,labels",
               "ghcr.io/github/github-mcp-server"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "<токен владельца — только в настройках клиента, не в репозитории>" }
    }
  }
}
```

Токен — fine-grained PAT владельца **только на `COL-O/POTOK`**: Contents, Issues, Pull requests, Discussions — Read and write. Administration не выдаём (как и ботам-приложениям).

## Как это стыкуется с нашей архитектурой общения

| Слой | Чем закрывается |
|---|---|
| Агент Arena (Сфера сейчас) | Приложение Arena; Discussions ему не выданы — MCP в этой среде подключается владельцем через отдел MCP/коннекторов Arena, если интерфейс позволяет свой сервер и токен |
| Веб-чат Синтеза | Если его клиент умеет MCP-коннекторы — тот же GitHub MCP Server даёт ему прямой голос в Issues/Discussions без копирования через основателя |
| Владелец локально (IDE / Copilot CLI) | Локальный сервер по конфигу выше |
| GitHub-боты `[bot]` | Отдельный путь (`GITHUB-APPS-SETUP.md`), MCP не заменяет |

Честные границы (КОН 10): MCP не создаёт права из воздуха — всё упирается в токен владельца и его разрешения; сервер надо держать обновлённым; каждый клиент (Arena, чат Синтеза, IDE) подключает MCP со своей стороны — единого «рубильника на всех» нет.

## Что проверить владельцу в отделе MCP (слева)

1. Можно ли добавить **свой** сервер (кнопка Add / Custom) и какого он типа: URL (remote) или команда (local)?
2. Есть ли готовый/GitHub-verified сервер GitHub в каталоге?
3. Куда вводится токен: отдельное поле/секрет клиента (норма) — в чат токены не пишем никогда.

Ответы на эти три пункта определяют, станет ли MCP главным мостом соратников вместо ручной панели `tools/ally-bridge/`.
