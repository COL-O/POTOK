# Ноутбуки Colab — лаборатория в браузере основателя

Основатель подключил Google Colab к проекту (2026-11-16; его первый ноутбук — приватный gist, пустой лист). Colab для ПОТОКА — **временная живая машина в браузере**: бесплатные CPU/GPU, Python, интернет; сессия живёт часы и умирает без следа, поэтому ноутбуки храним здесь, в git, а факты из них переносим в журналы.

## Как пользоваться

Рабочая связка дома: **Сфера пишет в Arena → коммит в GitHub → Colab открывает и выполняет → результат сохраняется обратно в GitHub.**

1. Сфера обновляет `.ipynb` в репозитории (Arena уже подключена к GitHub — сделано).
2. Основатель: Colab → File → Open notebook → вкладка GitHub → COL-O/POTOK → нужный ноутбук. Или прямая ссылка: `https://colab.research.google.com/github/COL-O/POTOK/blob/arena/3bbbb51d-potok/notebooks/<имя>.ipynb`
3. Запуск: Runtime → Run all. Если Сфера обновила код, пока Colab открыт, — перезапустить первую ячейку: она сделает `git pull` и подтянет свежее.
4. Сохранить результат: File → Save a copy in GitHub (в ветку, с сообщением коммита) — вывод ячеек станет фактом дома.
- Сфера пишет ячейки → основатель запускает (Runtime → Run all) → вывод виден основателю; итоги, ставшие фактом, Сфера забирает в LOGBOOK/RUN-LOG по словам основателя или скриншоту/копии вывода.
- **Секреты в ячейки не вставлять.** Токен, если нужен, — только скрытым вводом (`getpass`) на время сессии и никогда не сохранять ноутбук с ним.

## Управление блокнотом: кто что умеет (по документации Colab)

| Действие | Сфера (через git) | Основатель (в браузере) | Русло/CI |
|---|---|---|---|
| Писать и править ячейки, код, разметку | ✔ правит `.ipynb` и коммитит | ✔ правит прямо в Colab | — |
| Панель без кода (формы `#@param`, `#@title`) | ✔ закладывает в ячейки | ✔ выбирает значения полями | — |
| Нажать Run / выбрать рантайм | ✖ официального API запуска нет | ✔ Run all; **Runtime → Change runtime type**: CPU ↔ **T4 GPU** (проверка ячейкой `!nvidia-smi`) | — |
| Выполнить ноутбук без браузера | Заказывает ячейки | — | ✔ `papermill` / `jupyter nbconvert --execute`: тот же ноутбук, выводы вписываются в файл и коммитятся |
| Colab-интерфейс на своей машине | — | Подключает «Connect to local runtime» | ✔ у Русла: `jupyter_http_over_ws` — браузер основателя, исполнение и файлы на машине Русла |
| Открыть из GitHub | Готовит ссылку/бейдж | File → Open notebook → GitHub (нужна авторизация Colab в GitHub, есть доступ и к приватным) | — |
| Сохранить результат | Читает из репозитория | File → Save a copy in GitHub / в Drive | ✔ коммитит выполненный ноутбук |

Способы связи с GitHub по документации: открытие с вкладки GitHub и по прямой ссылке `colab.research.google.com/github/<владелец>/<репо>/blob/<ветка>/<файл>.ipynb`; бейдж «Open in Colab» в начале ноутбука; сохранение копией в GitHub; `git clone/pull` внутри ячеек (наш путь для рабочей ветки). Данные между эфемерными сессиями живут в git или смонтированном Drive (`google.colab.drive`), не в рантайме.

## Честные границы

Colab не заменяет машину Русла: среда эфемерна, Go ставится ячейкой, долгих процессов и входящих подключений нет. Это лаборатория опытов и запасные руки для Python-задач (разбор логов, метрики, GitHub Models), а не контур исполнения.
