# 02 — Шина (Кровеносная система)

**`bus/`** — типизированная шина поверх `unix.Mmap`. Zero-GC. Epoch Fencing. `OrganRegistry` (RCU).

**Роль**: «кровеносная система» организма — 10 дорожек, каждая под свой тип данных. Сборщик мусора Go (GC) не сканирует эти области — нет пауз Stop-The-World.

**КОН**: КОН 1 (движение, не деньги) — шина перекачивает чистые битовые и тензорные импульсы без накладных расходов на сериализацию.

---

## 1. Принцип SOA (Structure of Arrays)

**Проблема**: если положить в одну Go-структуру `Event` и битовый вектор HDC, и граф узлов, и `float32`-тензор — `front` (наносекунды) при чтении битов будет затягивать в L1-кэш мусор из соседних полей (False Sharing).

**Решение**: горизонтальное расслоение на 10 изолированных дорожек (Lanes), выровненных по 64 байтам (кэш-линия CPU), с фиксированным размером кольца `N = 2^k`. Индекс слота — одна битовая маска: `slot := eventID & (RingSize - 1)`.

---

## 2. Десять дорожек

### 2.1. Дорожка 0 — `LanePulse` (64 байта на слот)

**«Пульс»** — заголовок импульса, выровненный ровно под одну кэш-линию CPU. Читают и атомарно обновляют все контуры.

**Поля** (`EventHeader`, ровно 64 байта):

| Поле | Тип | Смещение | Назначение |
|---|---|---|---|
| `EventID` | `uint64` | [0..7] | Сквозной монотонный номер импульса |
| `Timestamp` | `int64` | [8..15] | Время входа (наносекунды) |
| `Sequence` | `uint32` | [16..19] | Поколение (эпоха) слота для Epoch Fencing |
| `StateFlags` | `uint32` | [20..23] | Атомарные битовые флаги состояния |
| `ActiveMask` | `uint32` | [24..27] | Маска запуска 21+ моделей от front |
| `VetoMask` | `uint32` | [28..31] | Маска запрета («контур боли») от polygon |
| `Confidence` | `uint32` | [32..35] | `float32` bits (итоговая уверенность) |
| `TTS` | `uint32` | [36..39] | Бюджет времени жизни события (критичность) |
| `GraphOffset` | `uint32` | [40..43] | Смещение в Дорожке 2 (`NullOffset` если нет) |
| `TensorOffset` | `uint32` | [44..47] | Смещение в Дорожке 3 (`NullOffset` если нет) |
| `MetaOffset` | `uint32` | [48..51] | Смещение в Дорожке 4 (`NullOffset` если нет) |
| `OwnerLayer` | `LayerID` | [52] | Текущий держатель аренды (Lease) |
| `Priority` | `uint8` | [53] | Приоритет для Rate Limiter префетчера |
| `ErrorCode` | `uint16` | [54..55] | Быстрый код ошибки (детали в Дорожке 5) |
| `Reserved` | `[8]byte` | [56..63] | Выравнивание до 64 байт |

**Compile-time проверка**: `var _ [64]byte = [unsafe.Sizeof(EventHeader{})]byte{}`.

**Флаги состояния** (`StateFlags`):

| Флаг | Значение | Назначение |
|---|---|---|
| `FlagReady` | `1 << 0` | Слот полностью записан и готов к чтению |
| `FlagSurprise` | `1 << 1` | Эскалация из front в polygon |
| `FlagEscalateToGrowth` | `1 << 2` | Эскалация из polygon в growth |
| `FlagVetoTriggered` | `1 << 3` | Сработал контур боли (VetoMask) |
| `FlagInQuarantine` | `1 << 4` | Обработано в режиме Карантина |
| `FlagHasError` | `1 << 5` | В Дорожке 5 зафиксирована ошибка |
| `FlagCommitted` | `1 << 6` | Финальный вердикт зафиксирован |

### 2.2. Дорожка 1 — `LaneHDC` (1280 байт на слот)

**«Нервный импульс»** — гипервектор `[160]uint64` (10 240 бит = 20 кэш-линий). Заблокирован в физической памяти (`unix.Mlock`) для наносекундного доступа слоя `front`.

**Compile-time проверка**: `var _ [1280]byte = [unsafe.Sizeof(HDCSlot{})]byte{}`.

**Доступ**: прямое индексирование по `slot := eventID & mask`. `front` использует для мгновенного XOR + Popcount. `stratos` — для индексации.

---

### 2.3. Дорожка 2 — `LaneGraph` (CSR-графы)

**«Топологическая дорожка»** — кольцевая арена CSR-графов поверх `unix.Mmap` без указателей Go.

**Формат блока** (16 байт заголовка):

| Поле | Тип | Назначение |
|---|---|---|
| `NumNodes` | `uint32` | Число узлов |
| `NumEdges` | `uint32` | Число рёбер |
| `Sequence` | `uint32` | Эпоха блока (Epoch Fencing) |
| `Checksum` | `uint32` | CRC32 (IEEE) контрольная сумма |

**Далее плотно упакованы**: `RowOffsets []uint32`, `ColIndices []uint32`, `EdgeWeights []float32`.

**Безопасность**: Bounds Check перед возвратом срезов `[]uint32` и `[]float32`. `NumEdges` не превышает лимит — исключён выход за пределы памяти даже при повреждении заголовка.

---

### 2.4. Дорожка 3 — `LaneTensor` (4D-тензоры)

**«Непрерывный поток»** — кольцевая арена 4D-тензоров `[Batch, Channel, Height, Width]` (`float32`), где полезная нагрузка выровнена строго по 64 байтам для инструкций AVX-512 и Zero-Copy передачи в C++/CUDA.

**Заголовок блока** (16 байт):

| Поле | Тип | Назначение |
|---|---|---|
| `DType` | `uint8` | `float32` / `int8` |
| `Dims` | `[4]uint16` | Размерности 4D |
| `Sequence` | `uint32` | Эпоха блока |
| `ByteLen` | `uint32` | Длина в байтах |

**Доступ**: возвращает типизированный срез `[]float32` (через `unsafe.Slice`), готовый для передачи в Mamba-3, CfC, KAN, Matrix Profile без копирования.

**Поля** (`MetadataSlot`, 64 байта):

**Compile-time проверка**: `var _ [64]byte = [unsafe.Sizeof(MetadataSlot{})]byte{}`.

## 3. Протокол согласованности (LMAX + Epoch Fencing)

### 3.1. Публикация (`Publish`)

1. **Захват билета**: писатель атомарно инкрементирует курсор: `id := bus.nextEventID.Add(1)`.
2. **Вычисление слота и эпохи**: `slot := id & bus.mask`, `seq := uint32(id >> bus.shift)`.
3. **Запись тяжёлых данных**: если есть граф или тензор, писатель резервирует кусок в `GraphArena` / `TensorArena` (помечая его текущей эпохой `seq`) и пишет данные.
4. **Запись битов**: пишет 1280 байт в `HDCSlot[slot]`.
5. **Атомарная публикация импульса** (Memory Barrier): заполняет поля `EventHeader[slot]`, записывает `Sequence = seq` и самым последним действием через `atomic.StoreUint32` выставляет флаг `FlagReady` в `StateFlags`. До этого момента ни один читатель слот не трогает.

### 3.2. Быстрое чтение (`ReadFast` — для `front`)

1. `front` проверяет `atomic.LoadUint32(&header.StateFlags) & FlagReady != 0` и сверяет `header.EventID == expectedID`.
2. Напрямую читает `HDCSlot[slot]` (20 кэш-линий) и вычисляет расстояние Хэмминга.
3. Атомарно обновляет `ActiveMask`, `Confidence` и при необходимости взводит `FlagSurprise` в `StateFlags`.

### 3.3. Безопасное чтение с защитой эпохи (`ReadSafe` — для `polygon` и `growth`)

Поскольку `polygon` работает миллисекунды, а `front` летает на наносекундах, применяется двойная проверка `Sequence` (Optimistic Lock):

1. `polygon` считывает `seqBefore := atomic.LoadUint32(&header.Sequence)` и проверяет, что `header.EventID == targetEventID`.
2. Копирует или обрабатывает данные из `GraphArena` / `TensorArena` (проверяя заголовок арены `arenaBlock.Sequence == seqBefore`).
3. После завершения чтения снова проверяет `seqAfter := atomic.LoadUint32(&header.Sequence)`.
4. Если `seqBefore != seqAfter` (кольцо обернулось и перезаписало слот во время чтения) — вердикт отбрасывается, а счётчик `RingOverrunCount` инкрементируется.

## 4. Управление памятью (`unix.Mmap`)

**`AllocRegion`** — память вне кучи Go:

- `unix.Mmap` с выравниванием по странице ОС.
- `lockInRAM == true` → `unix.Mlock` (pinned в RAM для `front`).
- `Prefetch` / `Evict` — обёртки над `unix.Madvise` (`MADV_WILLNEED` / `MADV_DONTNEED`).
- `Bounds` — проверка перед возвратом среза.

**`Mlock`** — только для `front` (Дорожки 0 и 1). `polygon` / `growth` — без `Mlock` (могут быть вытеснены).

---

## 5. `OrganRegistry` (RCU)

**`OrganRegistry`** — реестр органов с поддержкой атомарной горячей подмены (RCU HotSwap после Карантина).

**Ключевое**:
- `atomic.Pointer[organTable]` — мгновенная подмена.
- `HotSwap(org)` — CAS на таблицу (32 слота).
- `Get(id)` — 1 атомарное чтение указателя.

**`MaxActiveOrgans = 32`** — соответствует маске `uint32` (21 активное ядро + 11 наследие / резерв).

---

## 6. Метрики шины (`BusMetrics`)

**`BusMetrics`** — lock-free счётчики состояния и здоровья шины:

| Счётчик | Назначение |
|---|---|
| `PublishedCount` | Всего опубликовано импульсов |
| `RingOverrunCount` | Сколько раз кольцо перезаписало непрочитанный слот |
| `BackpressureCount` | Сколько раз polygon/growth пропустили кадр по Epoch Fencing |
| `BoundsErrorCount` | Попытки выхода за границы арен |
| `ChecksumMismatchCount` | Ошибки контрольной суммы CRC32 |
| `PrefetchCount` | Вызовы `MADV_WILLNEED` |
| `EvictCount` | Вызовы `MADV_DONTNEED` |

**`Snapshot()`** — согласованный срез текущих счётчиков без блокировки шины.
