# Разбор №2: смысл проекта и слои polygon / growth / stratos

> Дата фиксации: 2026-11-15. Поступила первая часть смысла проекта и детальное описание слоёв `polygon`, `growth`, `stratos`.
> Код по-прежнему не пишется: сначала структура модулей концептуально, потом интерфейсы (порядок задан автором).

## Смысл проекта — как я его теперь понимаю

**POTOK — саморазвивающийся, осмысленный организм внутри Go-сервера, со своей сферой общего поля («Сфера Вернадского»). Это система управления системой: 100 заводов в одном общем поле, в безденежной системе, как в одном организме.**

То есть прикладная рамка такая: не «ERP для одного завода», а общий организм на сотню заводов, где распределение идёт без денег — через факты, ёмкости, излишки, потребность и прецеденты. Полная фиксация: `docs/concept/project-meaning.md`.

## Контур организма (вытекает из описаний слоёв)

```
front ──факты/отклонения──► polygon ──антитело (правило)──► front
  ▲                            │
  │                            ├─ спор моделей? ─► запрос прецедента ─► stratos
  │                            ▼
  └────────────── прецеденты (stratos учит всех, не командует) ◄── stratos
                               ▲
growth ──почка/прецедент───────┘
  ▲
  └── излишки, гипотезы, новые узлы (из общего поля: graph, bim/capacity)
```

- **polygon** не голосует: иерархия аспектов (аномалия → причина → прогноз → правило → конфликт → пик), спор решается прецедентом из stratos. Продукт — **антитело** для front.
- **growth** не голосует: иерархия (ветки → формула → динамика → действие → новый узел → траектория), спор — тоже прецедентом. Продукт — **почка**, которая становится прецедентом в stratos.
- **stratos** не выбирает и не командует: отдаёт по запросу (front — правила, polygon — диагнозы, growth — сценарии, всем — длинные волны), хранит неизменяемо (цепочка SHA-256), учит.

Саморазвитие получается замкнутым контуром: каждое решение polygon/growth оставляет прецедент → stratos копит → следующие споры решаются по накопленной истории, а не с нуля.

## Что эта часть закрыла из вопросов разбора №1

1. **Состав front первой волны разрешён.** Теперь front = 7: HDC, Tsetlin, D* Lite, **MCTS**, TTL, Capacity, Pasport. Вариант с CfC/MPC из «первого шага» разбора №1 superseded — актуальна семёрка из свода слоёв и плана `modules/front/models.go`. MCTS в front — осознанно (разведчик веток нужен и рефлексу), а не ошибка.
2. **Арифметика 21 сошлась точно:** 7 (front) + 6 (polygon) + 6 (growth) + 2 (stratos) = **21 позиция**. В growth добавлен TD-MPC2 шестым (в разборе №1 было 5).
3. **KAN в polygon уточнён:** это KAN-диагност (FastKAN / LUT-KAN) — тот же LUT-KAN, что и в growth, но с другой задачей (причина сбоя vs «что можно собрать»). То есть межслойное переиспользование моделей — норма, а не исключение.
4. **SHA-256 в stratos прямо назван механизмом, не моделью.** Подтверждает гипотезу разбора №1: TTL / Capacity / Pasport / SHA-256 — механизмы слоёв, и в структуре модулей им место отдельно от моделей.

## Что осталось открытым (не блокирует фиксацию, нужно к структуре модулей)

1. **КОН.** В описаниях встретились ссылки: КОН 2 (факт, не суждение/приговор), КОН 4 (совместность), КОН 5 (время слоя: иммунитет и рост), КОН 7 (излишек — приглашение к росту), КОН 8 (деление), КОН 9 (память учит, но не командует). Формулировок самих КОНов пока нет — это, видимо, конституция организма. Без них нельзя формально проверить, что решение слоя «законно». Жду свод КОНов отдельной частью.
2. **Время growth плавает:** в своде слоёв — «часы–дни», в описании самого слоя — «недели/годы». Для контрактов это важно (таймауты, периодичность запуска). Оставил оба варианта, отметил в `project-meaning.md`.
3. **Новые сущности общего поля:** `graph` (граф заводов/связей), `bim` (источник capacity), BOM, «излишек», «почка», TTS. Ни одна пока формально не определена. TTS встречается во всех примерах как ключевой индикатор здоровья (падает при сбое, растёт от почки) — нужно его определение первым.
4. **«Сфера Вернадского» технически:** общее поле — это шина событий, общий граф, общее хранилище, всё вместе? От ответа зависит структура модулей сервера.
5. **Безденежная механика:** чем заменены цены при распределении между 100 заводами (потребность? приоритет? прецедент?). Пока видна только идея, не механизм.
6. **Слой front детально** ещё не описан (только состав из 7). Порядок автора: сначала структура наборов в модулях — видимо, front будет раскрыт там.
