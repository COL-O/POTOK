# Смысл проекта POTOK

> Зафиксировано со слов автора, 2026-11-15. Это часть смысла проекта — понимание будет углубляться по мере поступления следующих частей.

## Формула проекта

**POTOK — саморазвивающийся, осмысленный организм внутри сервера на Go, со своей сферой общего поля — «Сферой Вернадского».**

Кратко: **система управления системой** — 100 заводов в одном общем поле, в безденежной системе, как в одном организме.

## Что это значит по частям

### Организм, а не программа

Проект строится не как «приложение с функциями», а как организм:

- у него есть органы (7 функциональных органов моделей — см. реестр `docs/registry/models-55.md`);
- органы разнесены по слоям с разным характерным временем (front / polygon / growth / stratos);
- организм саморазвивается: слой роста (`growth`) ищет новое и отпочковывает «почки», слой памяти (`stratos`) накапливает прецеденты и учит остальные слои;
- организм осмысленный: решения принимаются не голосованием моделей, а по иерархии аспектов и по прецедентам из памяти.

### Сервер на Go

Организм живёт внутри Go-сервера. Отсюда требования к слоям:

- рефлекторный слой работает нативно и быстро (наносекунды–миллисекунды);
- тяжёлые модели подключаются через ONNX / C-ядро / GPU, не ломая ядро организма;
- подробности устройства сервера — в следующих частях пояснения.

### Сфера общего поля («Сфера Вернадского»)

У организма есть своя сфера общего поля. В терминах проекта это общее поле, в котором живут и взаимодействуют все участники системы (по аналогии со Сферой Вернадского — общим пространством, объединяющим всех в единую систему).

Как это поле устроено технически (шина? граф? общее хранилище событий?) — будет уточнено в следующих частях. В описаниях слоёв уже встречаются элементы этого поля: общий граф (`graph`), ёмкости/мощности (`capacity` из `bim`), прецеденты в `stratos`, доступные всем слоям по запросу.

### Система управления системой: 100 заводов

Прикладной смысл: POTOK управляет не одним объектом, а системой целиком:

- **100 заводов** находятся в одном общем поле;
- система **безденежная**: распределение и управление строятся не на деньгах/ценах, а на прямых связях — факты, ёмкости, излишки, потребность, прецеденты (механику ещё предстоит описать);
- заводы и потоки между ними ведут себя **как один организм**: рефлексы на местах (front), иммунитет системы в целом (polygon), рост и развитие (growth), общая память (stratos).

Примеры из описаний слоёв: сбой на заводе → polygon готовит «антитело» (правило перенаправления потока на соседний завод); излишек на одном заводе → growth предлагает «почку» (что можно собрать из излишка по BOM); всё случившееся → прецедент в stratos («ситуация → действие → результат»).

## Слои организма (кратко)

| Слой | Имя | Время | Что делает | Что отдаёт |
|---|---|---|---|---|
| `front` | Рефлекс | нс–мс | срабатывает, применяет готовые правила | факты, реакции |
| `polygon` | Иммунитет, «Совет управляющих» | минуты–часы | обсуждает отклонения, сравнивает с историей, готовит антитела | антитело (правило) для front |
| `growth` | Рост, «КБ Энтузиастов» | часы–дни (в описании слоя: недели/годы) | ищет возможности, стыкует излишки с гипотезами, отпочковывает почки | почку / прецедент для stratos |
| `stratos` | Память, «Вечность» | годы–века | хранит и отдаёт по запросу, учит, но не командует | прецеденты всем слоям |

Детально наборы моделей слоёв polygon, growth, stratos и то, как они решают: `docs/layers/polygon-growth-stratos.md`.

## Контур саморазвития (как слои связаны)

1. `front` живёт рефлексами и фиксирует факты/отклонения.
2. `polygon` разбирает отклонения: аномалия → причина → прогноз → правило → расписание; при споре моделей смотрит прецеденты в `stratos` и выдаёт `front` готовое **антитело**.
3. `growth` разбирает возможности: ветки → что можно собрать → динамика → действие → новый узел → траектория; результат оформляет как **почку/прецедент** в `stratos`.
4. `stratos` хранит всё в неизменяемой цепочке (SHA-256), отдаёт прецеденты по запросу любому слою и никого не командует — учит.

Организм, таким образом, учится на собственной истории: каждое решение оставляет прецедент, каждый прецедент делает следующие решения точнее.

## Что ещё не раскрыто (ожидается в следующих частях)

- Что такое КОН (в описаниях слоёв встречаются ссылки КОН 2, 4, 5, 7, 8, 9) — видимо, свод законов/принципов организма; нужны формулировки.
- Механика безденежной системы: чем заменяются цены и расчёты между 100 заводами.
- Устройство общего поля («Сферы Вернадского») технически: шина, граф, bim, хранилище.
- Что такое TTS (метрик, фигурирующие во всех примерах сбоев), состав данных с заводов, понятие «почки» формально.
- Слой `front` детально (пока описан только составом; polygon/growth/stratos раскрыты).
