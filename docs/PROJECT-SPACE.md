# Пространство проекта: целевая организация ПОТОКА

Чертёж «нормального дома» проекта по полной документации GitHub: где программируем, где общий чат, где круглый стол соратников. Собирала Сфера по официальным возможностям платформы; что уже стоит в личном контуре — помечено ✔, что переездом в организацию — ◐.

## Почему организация, а не личный аккаунт

Организация даёт то, чего у личного аккаунта нет: **команды и роли** (owner/member/moderator, кастомные роли), **проекты уровня организации**, **организационные Discussions**, **приложения во владении организации** (боты не зависят от личного аккаунта), org-wide правила (rulesets) и профиль-витрину организации. Репозитории переносятся в организацию из личного аккаунта переносом (Settings → Danger Zone → Transfer) **с сохранением истории, Issues, PR и релизов**.

## Состав дома ◐

| Репозиторий | Видимость | Роль |
|---|---|---|
| `POTOK` | публичный | Витрина и код организма: README, манифест, CI |
| `POTOK-INSIDE` | приватный | Закрытый контур соратников: внутренние ленты и решения |
| `podbor` | приватный | Внешнее дело основателя (приложение ПОДБОР) |
| `.github` | публичный | Профиль организации (`profile/README.md` — лицо дома) и общие файлы сообщества для всех репозиториев |

## Люди и роли ◐

| Команда/роль | Кто | Права |
|---|---|---|
| Owners | Основатель (COL-O) | Полный контроль организации |
| Команда «Круг» | Доверенные люди-соратники | Maintain на ключевых репозиториях: категории, закрепления, модерация |
| Команда «Соратники» | Участники с делом | Write: код, PR, обсуждения |
| Гости (outside collaborators) | Новички по приглашению | Triage/Write точечно на репозиторий |

Цифровые соратники людьми в организации не становятся: их присутствие — **GitHub Apps во владении организации** (`sfera-potok[bot]`, `synthes-potok[bot]`) + подписи `.mailmap`/Co-authored-by + личные комнаты в репозитории. ✔ (боты уже созданы Руслом в личном контуре; при переезде приложения переносятся/пересоздаются на организацию).

## Круглый стол ◐ (сердце общения)

Протокол заседаний (узлы, условия передачи слова, лимиты кругов, human-гейт) — по образцу графа ChatDev, на наших инструментах: [`docs/ROUND-TABLE.md`](ROUND-TABLE.md).

Три связанных слоя:

1. **Projects (доска круглого стола)** — проект организации «Круглый стол ПОТОКА»:
   - Виды: **Доска** (статусы: Принято → В работе → На проверке факта → Решено), **Таблица** (все вопросы с полями), **Дорожная карта** (итерации по неделям — у проекта есть поля дат и итераций);
   - Поля карточек: Соратник (Сфера/Синтез/Русло/основатель/круг), Этаж организма, Приоритет, Факт (ссылка на лог/прогон), Итерация;
   - Автоматика Projects: новая задача → в «Принято»; закрыта/слия PR → в «Решено». Доска не стареет, потому что движется сама.
2. **Discussions** — разговорная часть круглого стола: категории «📣 Объявления», «🪑 Круглый стол» (открытые), «💡 Идеи и смысл», «🙏 Вопросы» (Q&A с принятыми ответами), «🗳 Решения и голосования» (Polls). В закрытом контуре — те же категории внутри POTOK-INSIDE.
3. **Issues с метками** ✔ — оперативная лента: метки голосов (`сфера`, `синтез`, `русло`), `вопрос-кругу`, `решение`, `факт`, `живой-запуск` уже заведены в POTOK; общий чат — закреплённый Issue №4 ✔.

## Программирование (контур разработки) ✔/◐

- **Ветки и защита:** `main` — только через PR: обязательный зелёный CI (`POTOK Immune Check` ✔), ревью владельца кода (`.github/CODEOWNERS` ✔ заведён: основатель — владелец всего, особо — манифест и комната), запрет прямых пушей. В организации это усиливается rulesets на все репозитории сразу.
- **CI/CD:** Actions ✔ (тесты + сборка; мосты `ally-bridge.yml`, `synthes-mention.yml` дремлют до main и секретов).
- **Релизы и пакеты:** артефакты (APK и пр.) — Releases приватных репозиториев; Docker-образы организма — GitHub Packages (GHCR) организации при росте.
- **Документация:** docs/ в репозитории ✔ (источник правды в git); Wiki — только если понадобится свободно редактируемое пространство без ревью; GitHub Pages — витрина манифеста при желании.
- **MCP:** официальный GitHub MCP Server с набором `discussions` — подключение клиентов соратников, см. `community/MCP-GITHUB.md` ✔ (карта готова).

## Порядок переезда (шаги владельца и Русла)

1. Создать организацию (бесплатный план достаточен на старте), имя — на выбор: `potok-organism` / `organism-potok` (проверить доступность).
2. Перенести репозитории: POTOK, POTOK-INSIDE, podbor (Transfer в Danger Zone каждого; история и Issues переезжают целиком, старые адреса редиректят).
3. Создать команды «Круг» и «Соратники», раздать роли по таблице выше; базовое разрешение организации — Read, повышение — командами.
4. Переустановить/перенести ботов `sfera-potok`, `synthes-potok` на организацию; секреты — в секреты организации/репозиториев.
5. Создать проект «Круглый стол ПОТОКА» с видами и полями из чертежа; перенести в него живые задачи (Issue №4, №5 и successors).
6. Включить организационные Discussions либо оставить круглый стол на POTOK-INSIDE (решение круга).
7. Обновить ссылки в README/манифесте/памяти на новый адрес организации.

До переезда дом полностью живёт в личном контуре — чертёж не блокирует текущую работу ни в одном пункте.
