# OpenObserve — зрение организма: стык с ПОТОКОМ

Стык собран и проверен 19.11.2026. Это не «поставили программу», а **канал**: то, что
организм пережил, перестаёт исчезать после такта.

## Что поднято

| Часть | Где | Как включается |
|---|---|---|
| OpenObserve v1.1.2 | `~/openobserve`, данные `~/openobserve/data` | `systemctl --user start openobserve` (автозапуск включён) |
| Адрес | `127.0.0.1:5080` (только локально) | `/healthz`, `/web/` |
| Хранение | 30 дней (`ZO_COMPACT_DATA_RETENTION_DAYS=30`) | диск не забивается |
| Питание | `~/.config/opencode/o2_feed.py` | `o2-feed.timer`, раз в минуту |

Ключи: `~/.config/domovoy/secrets/openobserve-root.txt` (chmod 600, в репозиторий не попадают).

## Два потока

**1. `agent_events` — события ДОМОВОГО.**
Читает `~/.local/state/agent-events/events-ГГГГ-ММ-ДД.jsonl` инкрементально (курсор в
`~/.local/state/o2-feed/state.json`), отправляет новые строки в
`POST /api/default/agent_events/_json`. Проверено: 35 записей, повтор не дублирует.

**2. `potok_metrics` — метрики организма.**
Снимает `http://127.0.0.1:8080/metrics` (дашборд прозрачности) и кладёт снимок в
`potok_metrics`. Если организм не поднят — тихий выход, это нормальное состояние.

## Что это даёт

- **История вместо мгновения.** Дашборд `:8080/metrics` показывает «сейчас». O2 хранит
  «тогда»: сколько тактов было, когда пульс встал, как менялся `surprise_count`.
- **Чёрный ящик.** События ДОМОВОГО (что запускал, что сломалось, какой урок) лежат рядом
  с метриками — по ним можно строить запросы: «все события с `result` про CI за неделю».
- **Основа для ODK.** Полевые отправки — такой же поток JSON; эндпоинт тот же, отличается
  только имя потока.

## Проверка (факты, не намерения)

```bash
systemctl --user is-active openobserve        # active
curl -s 127.0.0.1:5080/healthz                # 200
python3 ~/.config/opencode/o2_feed.py all     # «отправлено записей: N» или тишина
```

SQL через встроенный CLI бинарника:

```bash
cd ~/openobserve
ZO_ROOT_USER_EMAIL=admin@example.com ZO_ROOT_USER_PASSWORD=... \
  ./openobserve sql -e "select count(*) as n from agent_events" -t 1d
```

Через REST: `POST /api/default/_search?type=logs` с `{"query":{"sql":"…"}}`.

## Ограничения, которые надо помнить

1. Community-версия: отдельный `o2-cli` (github.com/openobserve/o2-cli) — **только Enterprise**.
   Наш путь — подкоманды самого бинарника (`sql`, `reset`, `export`, `import`, `node`).
2. После `./openobserve reset -c root` нужен **перезапуск**: кэш пароля живёт в памяти
   (до рестарта API отвечает 401 — проверено).
3. Порт привязан к `127.0.0.1` нарочно: наружу сервис не выставлен.
4. Диск: свободно ~3 ГБ; retention 30 дней — страховка, но при большом потоке логов
   политику надо пересмотреть.
