## Диагноз шага «4 такта организма» в прогоне PR 22 (2026-11-20, по данным основателя)

Диагностическая ячейка показала дословно:

```

--- stdout ---
=== ИНИЦИАЛИЗАЦИЯ ЦИФРОВОГО ОРГАНИЗМА (4 КОНТУРА ВРЕМЕНИ) ===
--- stderr ---
Ошибка запуска HTTP-дашборда :8080: listen tcp :8080: bind: address already in use
```

То есть иммунитет (`go test -race ./...`, 5× флейк, `go build`) — зелёный, а бинарь падает на **фиксированном** `ListenAndServe(":8080")`: в рантайме Colab порт занят. Не дефект кода организма и не расхождение с CI (CI не запускает бинарь), а конфликт окружения. Варианты: освободить/убить занявший 8080 процесс в рантайме, либо одно коммитное изменение `cmd/organism/main.go` — чтение адресов из окружения (`ORGANISM_DASHBOARD_ADDR`, `ORGANISM_UDP_ADDR`) с теми же дефолтами (`:8080`, `:9000`). Требует слова основателя и отдельного коммита; до него бинарь в Colab не взлетит.

## Обход :8080 без правки кода (проверено запрещено только bind; такт-цикл порту не мешает)

Организм не нуждается в внешнем доступе к дашборду, чтобы отработать 4 такта. Если порт 8080 занят инфраструктурой Colab и освободить нечем, в ячейке Colab (root) можно запускать бинарь в отдельном сетевом пространстве:

```python
import subprocess
r = subprocess.run(['unshare', '-n', '/content/potok-pr22/bin/organism'],
                   cwd='/content/potok-pr22', capture_output=True, text=True, timeout=180)
print('код:', r.returncode); print(r.stdout); print('--- stderr ---'); print(r.stderr)
```

Порт внутри нового netns чист, bind проходит, процесс отрабатывает и завершается. Если `unshare: Operation not permitted` — остаётся только патч портов через окружение (ждёт слова основателя).
