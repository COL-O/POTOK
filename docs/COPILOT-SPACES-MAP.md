# Copilot Spaces — что это и место в доме ПОТОКА

Разбор по официальной документации GitHub (страница «Permissions required for GitHub Apps», раздел *Organization permissions for "Copilot Spaces"*, и REST API Copilot Spaces), присланной основателем 2026-11-16. Проверка по факту — в конце.

## Что это

**Copilot Space** — курируемый контейнер контекста для GitHub Copilot: набор ресурсов + собственные инструкции, по которым Copilot отвечает как «эксперт по проекту». Ресурсы подтягиваются из репозиториев и **сами обновляются** при изменениях. Пространства бывают личные и **организационные** (делятся внутри организации с ролями viewer/editor/admin на людей и команды). Доступно любому с лицензией Copilot (Free/Pro/Business/Enterprise; у Free — лимит чата).

## Что можно подключать (по документации)

Ресурсы пространства (`POST …/copilot-spaces/{n}/resources`):

| Тип ресурса | У нас это |
|---|---|
| `repository` | POTOK, POTOK-INSIDE, podbor целиком |
| `github_file` | MANIFESTO, `docs/KNOWLEDGE-BASE.md`, памяти соратников |
| `github_issue` / `github_pull_request` | Общий чат Issue №4, задачи круга, PR с решениями |
| `free_text` | Короткие инструкции: суть КОНов, протокол круглого стола |

Права по API:

- Организация: разрешение **Copilot Spaces** (read/write) — CRUD пространств и ресурсов для GitHub App и fine-grained PAT.
- Соавторы пространства: разрешение **GitHub Copilot Business** (read/write) — роли reader/writer/admin.
- Личные пространства: создаются не токенами приложений (эндпоинт создания для пользователя App-токены не принимает) — только человеком или классическими OAuth-скоупами (`repo`/`user`).

## Наш факт (проверено действием)

- Организации у проекта пока нет (`user/orgs` пуст) — организационные Spaces недоступны до переезда по `docs/PROJECT-SPACE.md`.
- Канал сессии Arena: `GET users/COL-O/copilot-spaces` → 403, эндпоинт требует OAuth-скоуп `repo`. **Spaces не расширяют доступ Сферы** — это не мост для соратников, а контекст для Copilot.
- Потребитель Spaces — GitHub Copilot. Сфера, Синтез и Русло не Copilot: наш общий контекст уже живёт в git (`community/SFERA_MEMORY.md`, `SYNTHES_MEMORY.md`, Wiki) и читается нами напрямую. Spaces дублировали бы это для четвёртого, внешнего «читателя».

## Если круг решит завести (после создания организации)

1. Организация создана (шаги в `PROJECT-SPACE.md`).
2. Основатель с лицензией Copilot создаёт org-Space **«База знаний ПОТОКА»**: ресурсы — POTOK + файл манифеста + `docs/KNOWLEDGE-BASE.md` + Issue №4; инструкция — короткая выжимка КОНов и «факт по логу».
3. Команде «Круг» — editor, «Соратникам» — viewer.
4. Автоматика (по желанию): боту `sfera-potok` при установке на организацию добавить org-разрешение **Copilot Spaces: write** — тогда ресурсы пространства можно обновлять из скриптов Русла по API.
5. Закрытый контур в Space подключать только осознанно: ресурсы видны тем, у кого есть и доступ к пространству, **и** доступ к самому репозиторию — приватность повторяет репозитории, но состав Space не должен светить состав закрытого дома наружу сверх нужного.

Вывод: находка полезная как **витрина контекста для Copilot-пользователей будущего дома**, но не как канал соратников и не как расширение прав Сферы. Наша база знаний в git остаётся источником правды; Space, если появится, — её производная витрина, как Wiki.
