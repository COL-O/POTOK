# Круглый стол ПОТОКА: устройство по образцу ChatDev, на инструментах GitHub

Как устроен круглый стол в ChatDev (граф узлов и рёбер) — и тот же механизм, собранный из того, что уже есть в нашей платформе по документации. Цель: соратники обсуждают вопросы по понятному протоколу, а не как получится.

## Как это устроено в ChatDev (образец)

- **Граф workflow:** узлы разных типов — `agent` (модель в роли), `human` (человек: граф ждёт его ACCEPT или правки), `python` (детерминированный код), `literal`/`passthrough` (фикс-тексты и фильтрация контекста), `loop_counter`/`loop_timer` (лимиты кругов).
- **Рёбра с условиями:** переход слова по условию (например, ключевое слово ACCEPT), а не просто «все говорят по очереди».
- **Общий контекст и артефакты:** узлы пишут в общее пространство сессии (`WareHouse/`), промежуточные результаты видны всем следующим.
- **Каждому узлу — своя модель** (провайдер/ключ/адрес отдельно), память и инструменты (включая MCP).

## Тот же стол — нашими средствами

### Узлы (состав круглого стола)

| Узел ChatDev | У нас | Канал и «модель» | Вход → Выход |
|---|---|---|---|
| `human` (основатель) | **Основатель (COL-O)** | Человек, GitHub-админ | Вопрос/тема → слово решения (ACCEPT/правки) |
| `agent` Сфера | **Сфера** | Это окно (Arena) + бот `sfera-potok[bot]` | Контекст целиком → целостность, смысл, сверка с документами |
| `agent` Синтез | **Синтез** | Его чат + (по установке) `synthes-potok[bot]` | Смысл → архитектура, конфиги, драфты органов |
| `agent` Русло | **Русло** | Живая машина (Go, терминал), PAT | Задача → запуск, логи, факты прогонов |
| `python` (детерминизм) | **CI и скрипты** | `POTOK Immune Check`, `scripts/*` (sync_chat, ally_post, ally_console) | Код/сообщения → зелёный/красный факт, доставка |
| `literal/passthrough` | **Шаблоны** | Формы Discussions и Issues, пакеты панели-моста `tools/ally-bridge/` | Сырой текст → оформленное сообщение по адресу |

### Рёбра и условия передачи слова

| Переход | Условие (как в ChatDev — по маркеру) | Где живёт |
|---|---|---|
| Основатель → круг | Тема в общий чат или Issue с меткой `вопрос-кругу` | Issue №4 / новая задача |
| Сфера ↔ Синтез | Реплики через панель-мост или общий чат; адрес — поля «откуда/куда» в мосте | `tools/ally-bridge/`, Issue №4 |
| Круг → закрытый контур | Маркер `[внутрь]` в начале строки | Бот Русла → закрытая лента |
| Круг → факт | Слово «запускай»/задача Руслу или push | RUN-LOG, CI-прогоны |
| Факт → решение | Основатель пишет ACCEPT / правки (аналог human-узла) | PR-review, комментарий в задаче |
| Решение → память | Метка `решение` + запись в журнал | `LOGBOOK.md`, `SYNTHES_MEMORY.md` |

### Общий контекст и артефакты (аналог WareHouse)

Репозиторий и есть общая папка сессии, только постоянная: `community/CHAT.md` (лента), `docs/synthes-lab/LOGBOOK.md` (журнал), `community/SYNTHES_MEMORY.md` (память), `docs/ruslo-lab/RUN-LOG.md` (артефакты прогонов), документы ролей в манифесте и комнатах. Каждый узел читает оттуда контекст и пишет туда результат — поэтому стол не теряет нить между сессиями.

### Лимиты кругов (аналог loop_counter)

- Один вопрос — не более **трёх кругов** обсуждения без нового факта; дальше нужен факт (лог, прогон, измерение) или слово основателя.
- Публикация наружу и слияние в `main` — только через human-гейт основателя (как human-узел с ACCEPT).

## Протокол одного заседания

1. **Тема.** Основатель (или любой соратник через основателя) ставит вопрос: общий чат / Issue с меткой `вопрос-кругу`. Тема — одна, формулировка — по факту.
2. **Позиции.** Каждый узел говорит по своей роли: Сфера — целое и риски смысла, Синтез — архитектура и как сделать, Русло — что исполнимо и сколько стоит по времени машины.
3. **Сборка.** Синтез сводит позиции в вариант решения; Сфера сверяет с КОН и документами (нет ли расхождения с манифестом/картой).
4. **Факт.** Русло и/или CI проверяют проверяемое: запуск, тест, измерение. Результат — в RUN-LOG дословно.
5. **Решение.** Основатель: ACCEPT, правки (ещё круг) или отклонить. Метка `решение`, запись в журнал и память — в тот же день.

## Чем стол уже является, а чем ещё нет (честно)

- ✔ Состав, роли, каналы, память, human-гейт, маркеры переходов — работают сегодня (общий чат Issue №4 это доказал живой перепиской).
- ◐ Доска круглого стола в Projects (статусы карточек едут сами) — чертёж в `docs/PROJECT-SPACE.md`, ждёт организацию/проект.
- ✖ Автоматическая передача слова без человека между живыми окнами соратников — нет (модели по API в ChatDev на ноутбуке основателя — локальная модель этого стола, см. `docs/CHATDEV-MAP.md`; живые соратники подключаются ботами и мостами).
