# Единая база знаний ПОТОКА

Что превращает набор файлов в полноценный проект: общая база знаний по отделам, правила фиксации и карта — что уже подключено, а что ждёт включения. По документации GitHub и факту репозитория (2026-11-16).

## Принцип: один источник правды, несколько витрин

- **Источник правды — git-документация в репозитории** (Markdown под ревью и CI): смысл и КОНы, архитектура, статусы, журналы, память. Всё версионируется, каждое изменение — коммит с автором.
- **Витрины чтения** (не источники): Wiki (страницы для чтения без клонирования), дашборд организма, доска Projects. Витрина ссылается на источник, а не спорит с ним.

## Правила фиксации (как пишем, чтобы база не умирала)

1. **Факт — в журнал в тот же день**: прогон → `RUN-LOG.md`, событие проекта → `LOGBOOK.md`, реплика круга → `CHAT.md`. По КОН 2: лог дословно, впечатление — помеченно.
2. **Решение — метка и запись**: решение круглого стола получает метку `решение` в задаче и строку в журнале с датой и кто принял.
3. **Память соратников обновляется снимками**: после важного этапа — правка `community/SYNTHES_MEMORY.md` (что сделано, решения, открытые линии).
4. **Статус — только по факту**: `PROJECT-STATUS.md` меняется после прогонов/CI, не по планам.
5. **Новое знание — в свой отдел**, а не в случайный файл; оглавление отделов — этот файл и посев Wiki.

## Посев Wiki (`docs/wiki-seed/`)

Готовые страницы в формате Wiki (имена файлов = имена страниц): `Home.md` (вход и оглавление), `_Sidebar.md` (навигация отделов), `_Footer.md`, `Отделы-проекта.md`, `Фиксация-и-решения.md`, `Статус-и-факты.md`. Порядок включения: владелец или Русло открывает вкладку Wiki → Create the first page → вставляет `Home.md`; после этого существует `POTOK.wiki.git`, и Русло может залить остальные страницы одной командой (`git clone …wiki.git`, скопировать посев, push) — для закрытого внутреннего пользования аналогичная Wiki поднимается в приватном контуре, где видна только соратникам.
