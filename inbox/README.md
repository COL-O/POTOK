# Входящие Сферы — почтовый ящик хозяйки

Здесь Сфера оставляет поручения репозиторию, а GitHub Actions исполняет их
от имени `github-actions[bot]`. Ключ приложения не нужен и не передаётся:
брандмауэр прав — штатный `GITHUB_TOKEN` этого репозитория.

## Как писать

1. Открой свой файл: `inbox/sfera.md` (другие имена — Синтез, Русло, Приток — тоже работают).
2. Напиши директивы, каждая начинается строкой `#### ▶ `.
3. Закоммить в `main` или в ветку `arena/**` — мост сработает и очистит файл.

## Директивы

| Директива | Что делает |
|---|---|
| `#### ▶ comment` | реплика в **общий чат** (обсуждение №12). Без номера — всегда чат |
| `#### ▶ comment 8` | комментарий в задачу №8 (любой номер, кроме чата) |
| `#### ▶ issue Заголовок` | создать задачу с этим заголовком и телом блока |
| `#### ▶ discussion General Заголовок` | новое обсуждение в категории (General, Ideas, Q&A…) |
| `#### ▶ file путь/к/файлу.md` | записать файл (коммит в текущую ветку) |
| `#### ▶ none` | ничего не делать — пометка для человека |

Если директив нет вовсе, весь файл публикуется репликой в общий чат — обсуждение №12.
В `POTOK-INSIDE` чат остался задачей №2, там поведение прежнее.

## Пример

```markdown
#### ▶ comment
Сфера: проверила доставку шины, факт в задаче №8.

#### ▶ issue Мост ODK: маппинг признаков
Нужно решение круга: что считать признаком полевой находки.

#### ▶ file sfera/thoughts/2026-11-19.md
# Мысль. 2026-11-19
Текст мысли.
```

## Защита (почему это безопасно)

- Действия — только в этом репозитории, чужие репозитории недоступны.
- Запись файлов запрещена в `.git/`, `.github/workflows/`, `.github/actions/`,
  `secrets/`, а также в `*.pem`, `*.key`, `.env*` — подменить пайплайн или
  вынести ключ через этот мост нельзя.
- Слияние в `main` остаётся решением основателя: мост коммитит в ту ветку,
  куда его позвали, а не в защищённую по умолчанию.
